# 手机通知

本智能体回答完成、被中断、弹窗需做决策时，经 Server酱（Server酱³）推送到手机。

## 什么时候推

| 时机 | 通知标题 |
| --- | --- |
| 一次回答正常结束（turn 正常完成） | 【智能体】已完成 |
| 回答被停止或被打断（用户中止、进程崩溃后回收） | 【智能体】已中断 |
| 弹窗提问（ask_user_question）或审批弹窗出现 | 【智能体】请决策 |

只推主会话；子代理会话的事件不推送，避免后台代理跑批时打扰。

## 通知格式

- 通知标题：【智能体】已完成 / 已中断 / 请决策
- 通知正文：会话标题（不足时回退最近一条用户提问，再回退「新会话」）
- 通知详情：回答正文（中断时为最近可见回答；请决策时为弹窗第一个问题或工具名+理由）

正文与详情都按显示位宽截断到 14 个全角位（全角字计 1、英文数字空格计 0.5），超出部分以「…」结尾；
详情先过滤 markdown 标记（星号、反引号、波浪号、下划线、行首井号、行首引用、链接只留文字、
表格剔分隔行并把竖线转空格、整行水平线剔除）再截断。

## 配置

在插件的 cordis.patch.yml 行里改：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `pushUrl` | 空 | Server酱³ 的 send 端点（含 SendKey）。本环境密钥登记在凭证容器「Server酱通知」卡片 |
| `enabled` | true | 总开关 |

单次推送超时 8 秒；推送失败只写宿主日志，不影响任何会话行为。

## 已知边界

- 详情取该轮最后一步的可见回答；多步回答的前几步不在通知里。
- 插件进程重启后，尚未发生过事件的旧会话标题与回答要等新事件流入才有值，期间以「新会话」兜底。
- 回答报错（接口失败等）不推送，按需求只做完成 / 中断 / 请决策三类。
- 本包仓库里的 cordis.patch.yml 不含真实 SendKey（占位空串）；真实推送地址配置在用户层 profile 的 cordis.patch.yml（phone-notify 行），不随仓库公开。
